# Donna Daily — static website

Built output: `public/` (index.html, editions/*.html, editions/index.html, data.json). Fully self-contained: inline CSS/JS, no external scripts, fonts or trackers. Photos are local files under `public/img/` (copied from `data/img/` at build time), never hotlinked. Readable without JS (Read more / About use native `<details>`); JS adds search, region/topic filters, chip filtering, the Back-to-top pill and shareable `?region=&topic=&q=` URLs.

## Layout
- `data/editions/*.json` — one file per edition (never edit old ones; they are the archive).
  - `kind:"edition"`: `{id, kind, title, date:"YYYY-MM-DD", leadId, notes:[], provenance?:[], stories:[{id, region: us|ca|hk|cn|world, topic: politics|business|culture|sports|human, ts:"YYYY-MM-DDTHH:MM", dateLabel, headline, deck?, summary, why, label, note?, sources:[{title, site, date?, href:"https://…"}], sourceChecks?:[…], image?}]}` (see Labels, Source checks and Photos below)
    - `notes` — short reader-facing notes (what's in/out of this edition, missing photos). Rendered only inside the collapsed **About this edition** near the footer, never above the lead. Do NOT write blanket production claims such as "every source and date was checked"; the build strips that wording from older editions and the tests fail if it appears.
    - `deck` (optional) — the 1–2 sentence front-page deck. If omitted, the build uses the first sentence of `summary` (two if the first is short). The rest of the summary, the note and the sources go in the card's **Read more**.
    - `provenance` (optional) — extra edition-level lines for About this edition (e.g. "Hong Kong government sites were slow this morning").
  - `kind:"archive"`: older Grok Page briefs converted by `tools/convert-archive.mjs` (personal travel section removed from the public copy).
- `data/state.json` — last successful build time (America/New_York), written only after a successful build.
- `tools/build.mjs` — validates (max 5 per region, https sources, required fields), builds into a temp dir, swaps into `public/`.
- `tools/linkcheck.mjs` — checks current edition's source links (401/402/403/406/429 or a network error = WARN, an access limit, not evidence of a broken link; 404/410 → FAIL) and writes `data/checks/<edition-id>-links.json` (`{edition, ranAt, method, results:[{url, status, tag, checkedAt}]}`, times ISO 8601 with the America/New_York offset). The build shows these as "Link opened (HTTP 200) · automated link check, <time>" under each source — it checks that a link opens, not what it says.
- `data/checks/` — automated link-check records (one per edition; keep old ones).
- `tools/test.mjs` — Playwright + Google Chrome at 360×844, 390×844, 430×844 (phone) and 1280/1440 (desktop). Checks: no horizontal overflow on every page; photos inside the viewport/column at 16:9 with width/height/alt, existing files and a linked credit (lead not lazy, lead loaded); lead headline + deck come before the lead photo and the lead h1 top is within the first 844px (at 390 the deck is fully visible too); the production note is only in the collapsed About this edition after the stories, with the sourcing note; search/filter sits above the lead; all 5 region controls + Past editions visible within the viewport width with no hidden scroll; 16–18px text; ≥44px targets on phones (≥24px desktop), incl. every `<summary>`; region/topic controls show story counts; each region chip filters to the right count and is marked active (aria-pressed + a different background); for every region, every topic (incl. an empty one) and a no-results search, **Latest (and the desktop rail) is hidden or non-empty**; empty topic/no-results show a message with a "Show all stories" reset that works; search counts; Read more expands and every story keeps its sources inside it; phones get a small fixed "↑ Top · Regions" button after scrolling that lands on the nav and is hidden at the top; `?region=ca` URLs; Past editions list and archive edition pages (5 region controls, Read more, About, link to today); no JS errors; no-JS reading (all stories, Latest ≤6, Read more works). Static checks on all built HTML: every `<a href>` is well-formed, external links are https, internal links and `#anchors` resolve inside `public/`; no blanket "Fact" badge and no "every source/story was checked" copy. Desktop: lead + Top stories rail side by side, ≥3-column region grids, black sticky nav with a working Sports button, ≤1264px content, ≤920px archive reading column. Screenshots to `screenshots/`: `first-screen-360|390|430.png`, `filter-canada-390.png`, `search-no-results-390.png`, `read-more-390.png`, `archive-edition-390.png`, `archive-oct29-390.png`, `desktop-1280.png`, `desktop-1280-full.png`, `archive-edition-1280.png`.
- `tools/update.sh` — the routine's one-command update: linkcheck → build → test (restore previous on failure) → optional `DEPLOY_CMD`.

The newest `kind:"edition"` file (by id, e.g. `2026-11-02-am` > `2026-11-01-ed1`) becomes the front page; all others are listed under Past editions.

## Responsive layout (one page, CSS media queries only; no user-agent sniffing, no separate URL)
- **Phones (<760px):** single column.
  - **Nav:** all five regions (with story counts) + Past editions as two tidy rows of three ≥44px pills — no horizontal scrolling. The active region is filled black with a red underline and `aria-pressed="true"`; tapping it again shows all stories.
  - **Search & filter** is a one-line collapsed `<details>` directly under the nav showing "21 stories" / "Showing 4 of 21"; it opens to search, Region and Topic selects (each option shows its count, e.g. "Culture & entertainment (0 — none this edition)") and a "Show all stories" reset.
  - **First screen (390×844):** masthead, nav, Search & filter, then the lead: kicker, headline, labels/date, deck — all visible without scrolling. The lead photo (credit in a one-line caption under it) follows, then Why it matters and Read more.
  - **Cards:** photo with compact credit line, labels, headline, ~2-sentence deck, "Why it matters", then **Read more** (`<details>`: the rest of the summary, the note, and **Sources & checks** — each source link with its check lines). Nothing is dropped; search still matches text inside Read more.
  - **Latest:** the 6 newest stories that match the current filters; the whole section (heading included) hides when nothing matches. Same rule for the desktop Top stories rail.
  - Empty results (no-results search or an empty topic) show a message ("No Culture & entertainment stories in this edition.") with a "Show all stories" button.
  - After ~700px of scrolling a small fixed "↑ Top · Regions" pill (bottom-right) jumps back to the nav. No sticky header, no modal.
  - **About this edition** (collapsed, after the region sections and Past editions): the edition notes, the sourcing note, the source checks on record and the automated link-check summary. Then **How to read the labels**.
  - Anything desktop-only carries `class="dt-only"` (hidden below 1024px; its images are `loading=lazy`, so phones never download them).
- **Tablet (760–1023px):** two-column region grids; nav pills wrap.
- **Desktop (≥1024px):** tabloid front page — full-width red masthead with an 82px wordmark, edition/date/update time on the left; black sticky section nav (US · Canada · Hong Kong · China · World · Sports, with counts · Archive; Sports toggles the topic filter via `data-tchip`); Search & filter bar (open by default) above the lead; lead story (condensed uppercase headline, deck, big photo) with a **Top stories** rail (first story of each region, thumbnails) and a numbered **Latest** rail beside it; region sections as 3-column (1024–1199px) or 4-column (≥1200px) grids with red section rules, a double-width feature card, and the last row filled using `data-n` (cards per section excluding the lead); hover states; black footer. Content max 1264px; archive and past-editions pages use a 920px reading column. No floating button (the nav is sticky).
- All of it lives in `tools/build.mjs` (CSS + templates), so every new edition, every archived edition page and the past-editions list get it automatically. The routine's steps are unchanged (`tools/update.sh`).

## Editorial rules
- **Labels describe the type of claim, not a verification grade.** Write `label` as one or more of these joined with " + " (e.g. `"Reported + official statement"`):
  - `Reported` — reported by the linked outlets; attributed to them, not independently confirmed by Donna Daily.
  - `Official statement` — a government's, official body's or company's own statement (variants the build understands: `Official figures`, `Company figures`, `Industry figures`, `Official proposal`, `Official forecast`).
  - `Claim` — an assertion by a person, government or group that hasn't been independently confirmed (e.g. Iran's conditional Hormuz offer).
  - `Allegation` — claimed, charged or argued in court; not proven.
  - `Analysis` / `Opinion` — interpretation, marked as such.
  - `Unnamed sources`, `State media` — the story rests partly on these.
  - Older editions' values are mapped at build time: `Fact` → Reported; `Fact (state media)` → State media; `Fact (government/official statement[s])` → Official statement; `Fact (government figures)` → Official figures; `Fact (company/industry figures)` → Company/Industry figures; `Fact (proposal)` → Official proposal; `Official forecast` stays; `Fact (preliminary)` → Reported (preliminary); `Fact + reported (unnamed sources)` → Reported + Unnamed sources; `Fact + opinion|analysis|allegation` → Reported + Opinion|Analysis|Allegation. Never render a bare "Fact" badge.
- **Tense:** describe scheduled events as planned/scheduled ("Trump set to close the campaign…") until a source reports they happened. Say "pilot", "participating banks", "proposal" etc. when the primary source does; don't imply general availability.
- **Sourcing copy:** don't claim every story or source was independently verified. The About this edition sourcing note says stories are compiled from the linked sources and labels reflect the type of claim.
- **Precise links:** link the specific article or press release, not a daily index/listing page (e.g. `info.gov.hk/gia/general/YYYYMM/DD/P….htm`, not `…/DD.htm`). If no precise URL can be found and opened, keep the index link and say so in `sourceChecks[].limits`.
- **Topic balance:** besides politics, actively look for worthwhile culture & entertainment and local-life (human interest) stories in each region — film, music, theatre, arts, food, city life — but never pad an edition with weak items. An empty topic is fine; the site marks it "(0 — none this edition)" and shows an honest empty state.
- **Personal details:** none about the reader on the public site.

## Source checks (optional `sourceChecks` per story)
`sourceChecks: [{url, publisher?, published?, checkedAt?, checkedBy, claimsSupported?:[…], limits?:[…]}]`
- `url` must be one of the story's source hrefs (https). `checkedBy` — who checked (e.g. "External reader audit, Nov 2 2026", "Donna Daily replacement-link check"). `checkedAt` — ISO 8601 with offset (`2026-11-02T09:10:07-05:00`); **leave it out if the time isn't documented — never invent check times or results.**
- `claimsSupported` — short list of what the page was confirmed to say. `limits` — paywall, access blocked, fetch failed but browser OK, unresolved, etc. A failed web fetch is an access limit, not evidence of a broken link or false reporting.
- Rendered under the matching source in Read more → Sources & checks, and listed in About this edition → Source checks on record, together with the automated link-check summary from `data/checks/`.

## Photos (optional `image` per story)
Aim to give the lead and most stories a photo. Skip a story rather than bend these rules.

**Field** (on a story): `image: {src, width, height, alt, caption?, credit, license, licenseUrl, sourcePage, isFilePhoto}`
- `src` — RELATIVE path `img/<edition-id>/<story-id>.webp` (the site is served from the repo root on GitHub Pages; the build adds `../` for pages under `editions/`). The file lives at `data/img/<edition-id>/<story-id>.webp`; the build copies all of `data/img/**` to `public/img/**`, so archived editions keep their photos. Use a new folder per edition (story ids repeat across editions). Never delete old edition folders.
- `width`/`height` — pixel size of the processed file (800×450).
- `alt` — what the picture shows. `caption` — short factual line saying what/where/when the photo is (e.g. "Wang Fuk Court in Tai Po, pictured in 2009."). Must not imply it shows the news event unless it really does.
- `credit` — author as given on the Commons file page (e.g. "Gunnar Klack", "National Park Service"). `license` — e.g. "CC BY-SA 4.0", "CC BY 2.0", "CC0 (public domain)", "Public domain (US government work)"; the build rejects anything else. `licenseUrl` — https link to the licence deed (for public domain, the Commons file page). `sourcePage` — https Commons file page.
- `isFilePhoto` — `true` when the picture is of the person/place/venue/flag rather than the event itself (nearly always). Rendered as **File photo**.
- Rendered: the lead gets a full-width 16:9 photo after its headline and deck (eager, `fetchpriority=high`); cards get a 16:9 photo above the label/headline (`loading=lazy`) on every screen size; on desktop the first card of each region is a double-width feature and the Top stories rail reuses the same files as 128×72 thumbnails (credited on the full story). Caption line: File photo · caption · Photo: credit (links to the Commons page) · licence (linked).

**Allowed sources only:** Wikimedia Commons files licensed CC0, public domain, CC BY or CC BY-SA (open the file page and confirm licence + author; avoid files tagged "review needed"/"license review" pending, or with unclear licence), and public-domain US government images (White House, NASA, NPS, military, etc.).
**Forbidden:** news-agency or outlet photos (AP, Reuters, Getty, AFP, Xinhua, outlet websites — also Commons files whose author is a news outlet or TV channel, e.g. am730, Box Azteca), anything with an unclear licence, logos as illustration, and AI-generated images.

**Processing:** download the Commons thumbnail (e.g. API `iiurlwidth=1280`), crop to 16:9 (shift the crop to keep faces/subjects), resize to 800×450, save WebP (quality ~70–78) under ~120 KB (Pillow is installed: `python3 -c "import PIL"`). Record each file in `data/img/<edition-id>/SOURCES.json` (story, Commons file, page, author, licence, licence URL). Cropped CC BY-SA images stay under the same licence (the caption links it).

Commons lookup that returns licence/author/thumbnail in one call:
`https://commons.wikimedia.org/w/api.php?action=query&format=json&titles=File:NAME&prop=imageinfo&iiprop=extmetadata|url|size&iiurlwidth=1280` (read `LicenseShortName`, `LicenseUrl`, `Artist`, `Credit`; send a descriptive User-Agent).
