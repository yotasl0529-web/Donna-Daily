# Donna Daily — static website

**Design:** the approved Nov 4, 2026 redesign is documented in `DESIGN.md` (type scale, colours, front-page structure, labelling and photo rules). Layout and CSS live only in `tools/build.mjs`; edition JSON is content only — future editions inherit the design automatically. Do not restyle per edition.

Built output: `public/` (index.html, editions/*.html, editions/index.html, data.json). Fully self-contained: inline CSS/JS, no external scripts, fonts or trackers. Photos are local files under `public/img/` (copied from `data/img/` at build time), never hotlinked. Readable without JS (Read more / About use native `<details>`); JS adds search, region/topic filters, chip filtering, the Back-to-top pill and shareable `?region=&topic=&q=` URLs.

## Layout
- `data/editions/*.json` — one file per edition (never edit old ones; they are the archive).
  - `kind:"edition"`: `{id, kind, title, date:"YYYY-MM-DD", leadId, notes:[], provenance?:[], stories:[{id, region: us|ca|hk|cn|world, topic: politics|business|culture|sports|human, ts:"YYYY-MM-DDTHH:MM", dateLabel, headline, deck?, summary, why, label, note?, sources:[{title, site, date?, href:"https://…"}], sourceChecks?:[…], image?}]}` (see Labels, Source checks and Photos below)
    - `notes` — short reader-facing notes (what's in/out of this edition, missing photos). Rendered only inside the collapsed **About this edition** near the footer, never above the lead. Do NOT write blanket production claims such as "every source and date was checked"; the build strips that wording from older editions and the tests fail if it appears.
    - `deck` (optional) — the 1–2 sentence front-page deck. If omitted, the build uses the first sentence of `summary` (two if the first is short). The rest of the summary, the note and the sources go in the card's **Read more**.
    - `provenance` (optional) — extra edition-level lines for About this edition (e.g. "Hong Kong government sites were slow this morning").
  - `kind:"archive"`: snapshot block-tree briefs (none at present; the old Oct 29 / Nov 1 briefs and the Nov 1 trial edition were removed on Nov 4, 2026). Still supported by the build and listed under Daily editions.
- `data/state.json` — last successful build time (America/New_York), written only after a successful build. Shown only in the footer as "Site last rebuilt …" (site maintenance time).
- `data/published.json` — **publication time of each daily edition** (ISO with offset), shown on the edition line ("Published Tue, Nov 3, 8:06 AM ET"). Values up to Nov 3 are the GitHub commit times of the publishing commits. When a new edition is built for the first time without `publishedAt`, the build records that build time here automatically; never edit a recorded time. An edition may instead set `publishedAt` itself.
- `data/site.json` — optional front-page notices `{notices:[{id, text, showUntil}]}` (e.g. a publishing pause). A notice shows only while the build time is before `showUntil`, so it disappears on the first rebuild after that. No personal details.
- Optional edition field `topIds:[…]` — the 4–5 supporting "Top stories" beside the lead (default: the first story of each other region).
- `tools/build.mjs` — validates (max 5 per region, https sources, required fields), builds into a temp dir, swaps into `public/`.
- `tools/linkcheck.mjs` — checks current edition's source links (401/402/403/406/429 or a network error = WARN, an access limit, not evidence of a broken link; 404/410 → FAIL) and writes `data/checks/<edition-id>-links.json` (`{edition, ranAt, method, results:[{url, status, tag, checkedAt}]}`, times ISO 8601 with the America/New_York offset). The build shows these as "Link opened (HTTP 200) · automated link check, <time>" under each source — it checks that a link opens, not what it says.
- `data/checks/` — automated link-check records (one per edition; keep old ones).
- `tools/test.mjs` — Playwright + Google Chrome at 360, 390, 430 (phones), 768 (tablet), 1280, 1286×683 and 1440 (desktop). Checks: no horizontal overflow or clipped text on every page; photos/thumbnails 16:9 inside their column with alt/size and a linked credit + licence (thumbnails ≤200px); edition line shows the publication time (not the rebuild time), footer shows "Site last rebuilt"; "Newer coverage" link only when a featured special was updated after the edition; pause notice matches `data/site.json`; lead headline + summary before/beside the photo and fully on the first 390×844 screen (bounding boxes); serif sentence-case headlines in the target sizes, sans metadata, white/near-black; search/topics panel closed by default; one lead + 4–5 supporting stories, every story exactly once, no Latest list; desktop lead ~2/3 with supporting column, ≥3-column regional sections, sticky region bar; All + 5 regions + Past editions visible without hidden scroll (Sports is a topic, not a region); touch targets ≥44px; text contrast ≥4.5:1; visible keyboard focus over 14 tab stops; every region, every topic, all 25 region+topic combinations (counts and empty states); search, unmatched search (message + reset, nothing else left visible) and Clear filters; accessibility snapshot free of stray +/−/arrow glyphs; story expansion with sources, claim basis and "Why it matters · Donna Daily analysis"; previews show only distinctive labels; file photos labelled; phone "Regions" button; `?region=&topic=` URLs; Past editions page (Daily then Special, counts, newest first); archived editions; no JS errors; no-JS reading. Specials: the tests below plus the Donna type system. Edge cases: builds a fixture (`/tmp/dd-fixture`, via `DD_DATA`/`DD_OUT`) with a ~170-character headline, no Hong Kong stories, no culture stories and no photos on the lead/World, and checks wrapping, first screen, text-only cards and honest empty states. Screenshots: `screenshots/redesign-after-*.png` (home 390×844 / 1280×800 / 1286×683, expanded story, Past editions, Canada filter, no-results search, edge case) plus the special-edition shots listed below.
- `tools/update.sh` — the routine's one-command update: linkcheck → build → test (restore previous on failure) → optional `DEPLOY_CMD`.

The newest `kind:"edition"` file (by id, e.g. `2026-11-03-am` > `2026-11-02-pm`) becomes the front page; all others are listed under Past editions in two separate groups, each newest first with a count in its heading: **Daily editions** (every older `kind:"edition"`/`archive` file) and **Special editions** (every `data/specials/*.json`). The same two groups appear in the front page's Past editions section. New daily files land in Daily and new specials in Special automatically.

Maintenance rebuilds that publish no new edition can run `DD_KEEP_UPD=1 node tools/build.mjs` to keep the previous "Last successful update" time from `data/state.json`.

## Special editions (`data/specials/*.json`, e.g. the October 2026 month in review)
- One file per special: `data/specials/<id>.json`, rendered by `tools/build.mjs` to `public/editions/<id>/index.html` (relative prefix `../../`). Example: `data/specials/2026-10-review.json` → `/editions/2026-10-review/`.
- Schema: `{kind:"special", id, title, date:"YYYY-MM-DD" (publication), publishedLabel?, period?:{from,to}, leadId, intro, notes?:[], provenance?:[], stories:[…]}`. Each story: `{id, section: news|life|opinion|culture, region: us|ca|hk|cn, alsoRegions?:[…], ts:"YYYY-MM-DD", dateLabel, headline, deck, summary, why, label, note?, sources:[{title, site, date?, href}], sourceChecks?:[…], image?}` (same `sourceChecks` and `image` rules as daily editions; a `sourceChecks[].url` must be one of the story's own source links, and `checkedAt` is only written when the time was actually logged).
  - Opinion stories also need `opinionKind`: `"ourview"` (Donna Daily's own analysis; `author:"Donna Daily"`, label `Our view`, must set out more than one side and link the underlying reporting) or `"column"` (another outlet's writer, paraphrased; requires `author` and `outlet`, label `Opinion`).
  - `alsoRegions` puts a cross-region piece under more than one region filter; region counts and filters both use `region + alsoRegions`.
  - Globe and Mail links are cited with `site:"The Globe and Mail (subscriber)"`; state media is named in `site` (e.g. "Xinhua (state media)") and labelled `State media`.
- Page: serif headlines, thin rules, the Donna deep-red accent and compact Donna Daily wordmark with the special's italic name (*Review*, *Election*). Section tabs (All/News/Life/Opinion/Culture) and region buttons (All/US/Canada/HK/China) show live counts; search; compact cards with Read more; Opinion split into **Our view** and **What columnists are arguing**; "Month at a glance" timeline (hidden when a filter leaves it empty, max 12 items); collapsed About this edition (notes, sourcing, provenance, every source check); label legend; Back to top; `?section=&region=&q=` URLs. Phones: single column, wrapping controls, ≥44px targets, lead headline + deck on the first screen. Desktop ≥1024px: lead with the timeline beside it, sticky section bar, 3-column grids (4 at ≥1280px).
- Optional per-special config (defaults reproduce the October special): `sectionLabels:{key:label}` and `regionLabels`/`regionShort`/`regionPhrases` (replace the fixed section/region sets, e.g. the midterms special uses senate|house|states|ny|next|opinion and national|northeast|south|midwest|west|world); `glanceTitle`, `unitLabel`, `wordmark`, `searchHint`, `ourViewIntro`, `strapLabel`; `updatedAt` (ISO with offset, shown as "Last updated …" in ET in the kicker); `glanceIds` and per-story `glance` (short text) / `order`; `featured:true` with `bannerHeadline` (the first featured special that was updated after the current daily edition's publication time gets a compact "Newer coverage" line above the lead, with its "Updated …" time; the daily edition stays the front page; `bannerKicker`/`bannerDeck` are no longer shown); `test:{search, combo:[sec,reg], share:[sec,reg], ourView:[min,max], columnsMin}` for `tools/test.mjs`. Story `ts` may carry a time (`YYYY-MM-DDTHH:MM…`) only when the time was actually verified.
- Midterms 2026 special: `data/specials/2026-11-midterms.json` → `/editions/2026-11-midterms/`, photos in `data/img/2026-11-midterms/` (credits in `SOURCES.json`). Race calls follow AP unless a story says otherwise; uncalled races are written as leads.
- Labels: specials add `Our view` (`lab-ov`) to the label set; it is not used in daily editions and is not shown in the daily legend.
- Linking: specials are listed under Special editions in Past editions (front page and `editions/index.html`); a featured, newer special also gets the "Newer coverage" line. `data.json` lists them under `specials`.
- **Keep rule:** specials are never edited by the twice-daily routine, never become the front page (the newest `kind:"edition"` file does), and are rebuilt on every run. Do not delete or move `data/specials/*`, `data/img/<special-id>/` or `data/checks/<special-id>-links.json` when writing a new daily edition.
- Link check for a special: `node tools/linkcheck.mjs 2026-10-review` (writes `data/checks/2026-10-review-links.json`; `update.sh` only re-checks the current daily edition).
- Tests (`tools/test.mjs`) for every special at 360/390/430 phone and 1280/1440 desktop: no overflow; photos 16:9 inside their column with linked credit and licence; title → controls → lead headline + deck before its photo, and on the first screen on phones; 1+N section tabs + 1+N region buttons (from the special's config) + search visible without hidden scroll; counts match the data; each tab and region filters to the expected count and is marked active, section counts follow the region; Opinion has the configured number of Our view pieces and named columnists; "last updated" ET time at the top when `updatedAt` is set; home banner links to a special; combined filter; search and no-results (message + reset, timeline hidden); Read more; every story has deck, Why it matters, a label and sources; desktop multi-column with the timeline beside the lead; Back to top; shareable URL; no JS errors; no-JS reading; home link and Past editions order; static link checks on the special page. Screenshots (`october-*` for 2026-10-review, `<id>-*` for others): `october-390.png`, `october-opinion-390.png`, `october-hk-390.png`, `october-search-none-390.png`, `october-1280.png`, `october-1280-full.png`, `home-390.png`.

## Responsive layout (one page, CSS media queries only; see DESIGN.md)
- **Phones (<760px):** compact masthead (wordmark + Past editions), edition line (publication time; pause notice), region bar All · US · Canada · HK · China · World (≥44px, no scrolling) with the **Search & topics** disclosure under it, the "Newer coverage" line, then the lead (kicker, serif headline, attribution, summary, photo, Why it matters, expansion), the 4–5 text-only Top stories, and compact regional lists with small thumbnails. A small fixed "↑ Regions" pill appears after ~700px of scrolling. No sticky header.
- **Tablet (760–1023px):** full region names, two-column regional sections, larger thumbnails.
- **Desktop (≥1024px):** sticky region bar with Search & topics at the right; lead about two-thirds wide (headline across, deck + Why it matters beside a medium photo) with the Top stories column beside it; three-column regional sections; Past editions/About/labels below; 1200px max content width, 880px reading column on the Past editions page.
- All of it lives in `tools/build.mjs`, so every new edition, every archived edition page and the Past editions list get it automatically. The routine's steps are unchanged (`tools/update.sh`).

## Editorial rules
- **Labels describe the type of claim, not a verification grade.** Write `label` as one or more of these joined with " + " (e.g. `"Reported + official statement"`):
  - `Reported` — reported by the linked outlets; attributed to them, not independently confirmed by Donna Daily.
  - `Official statement` — a government's, official body's or company's own statement (variants the build understands: `Official figures`, `Company figures`, `Industry figures`, `Official proposal`, `Official forecast`).
  - `Claim` — an assertion by a person, government or group that hasn't been independently confirmed (e.g. Iran's conditional Hormuz offer).
  - `Allegation` — claimed, charged or argued in court; not proven.
  - `Analysis` / `Opinion` — interpretation, marked as such.
  - `Unnamed sources`, `State media` — the story rests partly on these.
  - Older editions' values are mapped at build time: `Fact` → Reported; `Fact (state media)` → State media; `Fact (government/official statement[s])` → Official statement; `Fact (government figures)` → Official figures; `Fact (company/industry figures)` → Company/Industry figures; `Fact (proposal)` → Official proposal; `Official forecast` stays; `Fact (preliminary)` → Reported (preliminary); `Fact + reported (unnamed sources)` → Reported + Unnamed sources; `Fact + opinion|analysis|allegation` → Reported + Opinion|Analysis|Allegation. Never render a bare "Fact" badge.
- **Tense:** describe scheduled events as planned/scheduled ("Trump set to close the campaign…") until a source reports they happened. Say "pilot", "participating banks", "proposal" etc. when the primary source does; don't imply general availability.
- **Sourcing copy:** don't claim every story or source was independently verified. The About this edition sourcing note says stories are compiled from the linked sources and labels reflect the type of claim.
- **Precise links:** link the specific article or press release, not a daily index/listing page (e.g. `info.gov.hk/gia/general/YYYYMM/DD/P….htm`, not `…/DD.htm`). If no precise URL can be found and opened, keep the index link and say so in `sourceChecks[].limits`.
- **Topic balance:** besides politics, actively look for worthwhile culture & entertainment and local-life (human interest) stories in each region — film, music, theatre, arts, food, city life — but never pad an edition with weak items. An empty topic is fine; the site marks it "(0 — none this edition)" and shows an honest empty state.
- **Personal details:** none about the reader on the public site.

## Source checks (optional `sourceChecks` per story)
`sourceChecks: [{url, publisher?, published?, checkedAt?, checkedBy, claimsSupported?:[…], limits?:[…]}]`
- `url` must be one of the story's source hrefs (https). `checkedBy` — who checked (e.g. "External reader audit, Nov 2 2026", "Donna Daily replacement-link check"). `checkedAt` — ISO 8601 with offset (`2026-11-02T09:10:07-05:00`); **leave it out if the time isn't documented — never invent check times or results.**
- `claimsSupported` — short list of what the page was confirmed to say. `limits` — paywall, access blocked, fetch failed but browser OK, unresolved, etc. A failed web fetch is an access limit, not evidence of a broken link or false reporting.
- Rendered under the matching source in Read more → Sources & checks, and listed in About this edition → Source checks on record, together with the automated link-check summary from `data/checks/`.

## Photos (optional `image` per story)
Aim to give the lead and most stories a photo. Skip a story rather than bend these rules.

**Field** (on a story): `image: {src, width, height, alt, caption?, credit, license, licenseUrl, sourcePage, isFilePhoto}`
- `src` — RELATIVE path `img/<edition-id>/<story-id>.webp` (the site is served from the repo root on GitHub Pages; the build adds `../` for pages under `editions/`). The file lives at `data/img/<edition-id>/<story-id>.webp`; the build copies all of `data/img/**` to `public/img/**`, so archived editions keep their photos. Use a new folder per edition (story ids repeat across editions). Never delete old edition folders.
- `width`/`height` — pixel size of the processed file (800×450).
- `alt` — what the picture shows. `caption` — short factual line saying what/where/when the photo is (e.g. "Wang Fuk Court in Tai Po, pictured in 2009."). Must not imply it shows the news event unless it really does.
- `credit` — author as given on the Commons file page (e.g. "Gunnar Klack", "National Park Service"). `license` — e.g. "CC BY-SA 4.0", "CC BY 2.0", "CC0 (public domain)", "Public domain (US government work)"; the build rejects anything else. `licenseUrl` — https link to the licence deed (for public domain, the Commons file page). `sourcePage` — https Commons file page.
- `isFilePhoto` — `true` when the picture is of the person/place/venue/flag rather than the event itself (nearly always). Rendered as **File photo**.
- Rendered (DESIGN.md → Photos): the lead gets a medium 16:9 photo after its deck on phones and beside it on desktop (eager, `fetchpriority=high`) with the caption line "File photo, <year> · caption · Photo: credit (linked) · licence (linked)"; regional cards get a small 16:9 thumbnail beside the text with a one-line credit under the card (full caption in the expanded view); supporting Top stories are text-only. Optional `image.year` sets the file-photo year; otherwise the first year in the caption is used.

**Allowed sources only:** Wikimedia Commons files licensed CC0, public domain, CC BY or CC BY-SA (open the file page and confirm licence + author; avoid files tagged "review needed"/"license review" pending, or with unclear licence), and public-domain US government images (White House, NASA, NPS, military, etc.).
**Forbidden:** news-agency or outlet photos (AP, Reuters, Getty, AFP, Xinhua, outlet websites — also Commons files whose author is a news outlet or TV channel, e.g. am730, Box Azteca), anything with an unclear licence, logos as illustration, and AI-generated images.

**Processing:** download the Commons thumbnail (e.g. API `iiurlwidth=1280`), crop to 16:9 (shift the crop to keep faces/subjects), resize to 800×450, save WebP (quality ~70–78) under ~120 KB (Pillow is installed: `python3 -c "import PIL"`). Record each file in `data/img/<edition-id>/SOURCES.json` (story, Commons file, page, author, licence, licence URL). Cropped CC BY-SA images stay under the same licence (the caption links it).

Commons lookup that returns licence/author/thumbnail in one call:
`https://commons.wikimedia.org/w/api.php?action=query&format=json&titles=File:NAME&prop=imageinfo&iiprop=extmetadata|url|size&iiurlwidth=1280` (read `LicenseShortName`, `LicenseUrl`, `Artist`, `Credit`; send a descriptive User-Agent).
